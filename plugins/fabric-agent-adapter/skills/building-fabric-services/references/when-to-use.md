# When to use building-fabric-services

The skill's full trigger description, kept here so the front matter's `description` stays within the client's skill listing budget (about 350 characters a skill). Read it when choosing between this skill and a neighbour.

Use when running an agent as a Fabric service (fabric-service/0.1, its kits and probe): a local service (launchd, systemd, Windows), an ONLINE agent or dashboard on https, its dashboard link and kit (narrow panel, themes), data and cache paths, how callers reach and authenticate it, long jobs (fabric.job.*), spend report and limits, runner routes and model profiles, the estate record and delegation tokens, answering a Project's board requests, or packing and signing it. «сделай агенту дашборд», «локальный сервис агента», «подключи агента к Fabric Dashboards», «отвечать на запросы с доски проекта», «расходы агента на модели», "make this agent a local service", "make an online dashboard a Fabric service", "add the well-known endpoint". NOT for a one-off script or cron job, a hosted product with no agent, the provider manifest (adapting-projects-to-fabric), a new agent's design (creating-fabric-agents), a session using Fabric or its board (working-with-fabric), or building the Dashboards app (window, tray).
