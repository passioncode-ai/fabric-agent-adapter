## Decisions

- Reading is opt-in: the kit cannot tell the operator's personal board from an organization's (`com.status` names
  neither, read 2026-11-03), so the service names the sender Projects it trusts, or `PERSONAL_BOARD`. Default: none.
- No `callerAgent`: the board names a Project's principal, not an authenticated agent id, so the chain's end alone
  binds the mandate (MD-3).
- The handler records `recordAs`; the kit puts the operator's words in no event, log or checkpoint.
- The contract on board thread `118f95f9` (2026-11-03, message `adf0c61a`): its answer `7f372925` was inexact, a chain
  starts again only at an agent given an OA-3 relay. The full-chain restatement added in readings 5 to 8 is removed:
  past four agents the parts go only as an OA-3 relay (his Project on the board or his local session), whose receiver
  states its own (OA-2), never for a task it already leads (the contract's proposed minimum);
  a service has no route past four until CT-205. The code test of the restate route is replaced by one that a fifth
  hand-on is refused, by its problem name: a guard on MD-2 as it already stood, not a pin of this change (the
  prose pins keep the removed sentences out).
