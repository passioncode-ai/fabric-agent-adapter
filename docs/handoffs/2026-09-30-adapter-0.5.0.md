# Handoff: 0.5.0 — fabric-interop/0.1 in the kits, provider entries, one contract pin (2026-09-30)

## Objective

Module AR-1.6 of Fabric's agent-registry plan: the kits emit trace context and job
handles, the skills teach interop, the kit gains a `providers/` writer, the probe gains
the interop rules, and the adapter pins the new contract revision in one place (G-11).
The contract side (AR-1.1…AR-1.5) landed first in fabric-agent-contract #8–#11; its
record is that repository's `docs/evidence/plans/2026-09-30-ar1-contract.md`.

## Done

- **Kits.** `building-fabric-services/scripts/fabric_interop.py` and `fabric-interop.mjs`:
  trace context, capability → tool, durable `JobStore` (same file format in both), result
  envelope with usage, elicitations; Python `McpToolServer` with `fabric.job.get` /
  `fabric.job.cancel`. Events take a `traceId`/`spanId` pair.
- **Sample service** serves MCP at `/mcp` (`sample.echo`; `sample.draft`, a job with a
  title choice) and `register` writes its manifest, which names the descriptor (G-07).
- **Probe**: seven `interop.*` rules; it calls only `tools/list` and `fabric.job.get` for
  a made-up id.
- **Provider writer**: `adapting-projects-to-fabric/scripts/fabric_provider.py`.
- **Scaffolder**: an `mcp` capability requires `tool:<capability>`; `--job` writes the
  interop block; `check` refuses a malformed block.
- **One pin**: `fabric-contract.lock.json` = contract `0.1.0` at
  `a22dea359ba04b8fe549abe81a5131552cb90eff`; `test/validate.py` fails any live file that
  names another revision. All seven stale mentions moved.
- Skills: `references/interop.md`, `references/provider-entry.md`, step 4b; evals first
  (two trigger queries and three plus two scenarios).
