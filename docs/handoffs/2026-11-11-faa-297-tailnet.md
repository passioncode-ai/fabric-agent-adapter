# FAA-297: identity behind `tailscale serve` (0.78.0)

- **Objective.** One kit module for an agent behind `tailscale serve`, asked on the project board by studio-agent
  (request `2f0761d0-c4f3-4a1d-ad45-0eed6810a8fb`, 2026-11-11, the eSIM Studio review, item B2): the person from
  `Tailscale-User-Login`, groups from a perimeter generated from the organization's access registry, a personal key for
  MCP no wider than the groups, refusals 401/403 with a reason.
- **Done.** `fabric_tailnet.py` and `fabric-tailnet.mjs` (L0) in
  `plugins/fabric-agent-adapter/skills/building-fabric-services/scripts/`; shared vectors
  `test/fixtures/tailnet/vectors.json`; tests `test/test_fabric_tailnet.py`, `test/fabric-tailnet.test.mjs`; reference

  FAA-297; every version at 0.78.0 (`kit.json` included, as `test_fabric_kit` requires).
- **Decisions.** The header is believed only on serve's own listener from a loopback peer; on any other listener a
  request carrying serve's headers is refused (`serve-header-off-serve`). A perimeter without `generatedFrom` is
  refused (`perimeter-not-generated`), so a hand-kept file cannot pass. Regular expressions end in `\Z`: `$` let a
  login with a trailing newline through (`test/validate.py` R1 caught it).
- **Checks run.** `python3 test/validate.py` OK; the module's own tests pass in both languages. Failing on clean `main`
  before this change too, not touched here: `test_dashboard_kit.Cli` (3 tests) and the key-file test of
  `fabric-package` in Python and Node (an `openssl` on this machine).
- **Open.** The tag `v0.78.0` (npm publication) was not pushed: the run had no person in it and publication is a
  person's step. The generator from a concrete registry (Appvillis's, later Vesta roles) belongs to the consumer. An
  HTTP wrapper in `fabric_service.py` that calls `authorize` on a serve listener is a later step if a second consumer
  asks.
- **Next task.** Release 0.78.0: push tag `v0.78.0` on the merged commit, watch `release.yml`, confirm the npm package,
  then answer the board thread `d67439fb-fe58-4706-bc02-d16dd693813e` with the published version.
