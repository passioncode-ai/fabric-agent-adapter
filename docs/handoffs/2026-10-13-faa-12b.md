## Decisions

- **Project ids and capability names are compared as written, not by normal form.** The brief said to use
  `same_identifier`. But contract `identifiers.md` ("Compared as written") and DEC-0077 §2 say board Project ids and
  capability names are not URIs. `same_identifier` is used where DEC-0076 applies: two evidence ids naming one artifact.
  A uuid Project id is lower-cased before `fabric.board.join`, as Fabric's board does.
- **No `com.claim` read-back** (DEC-0078). Transferred attempts come only from the replace receipt. Without
  `transferred`, the request stays `held` with a notifying event. Fabric's ADR-0149 Amendment 1 read-back is never
  used.
- **Accepted work whose own lease lapsed** goes back to this responder by `com.responder_replace` with a transfer (the
  generation grows). Claimed work is dropped, and the next claim takes it again.
- **The idle slot's lease is kept by the holder's `com.enroll`** with a fresh key every ~20 s. That is the only renewal
  migration 87 offers without an attempt; it stores one receipt per renewal.
- **A board session never sends `com.submit`, `com.cancel`, `com.read_ack` or `com.directory`.** This is Fabric's fix
  round, which narrows the board session. The directory belongs to a Project session; `find_project` serves it.
- **A `com.status` without `idempotency.epoch` fails closed** (`no-epoch`, `board.blocked`). Fabric `main` gives none to
  a board session before its fix round, so against today's Fabric the responder waits rather than guess an epoch.
- **One request at a time per Responder.**
- **The input gate is required.** A refusal accepts the request and completes it `failed_known` with the gate's
  sentence. A redacted body is refused the same way.
- **Event data uses `reason`, not `code`.** FAC-SEM-101 counts `code` as a credential's name.
- **Branch history:** `main` was merged into the branch instead of a rebase, so nothing was force-pushed.
