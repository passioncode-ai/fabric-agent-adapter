# Handoff: 0.4.1, strict SKILL.md front matter (2026-09-29)

## Objective

Fix the BLOCKER from the 2026-09-29 audit. `building-fabric-services/SKILL.md:3` had an
unquoted `description:` holding `: ` ("fabric-service/0.1 extension: which surface",
column 493), which a strict YAML reader rejects. Make the validator able to see this class of
defect, and release 0.4.1 on GitHub. Publishing to npm stays the operator's decision.

## Done

- `test/validate.py`: `parse_frontmatter` is now a strict, stdlib-only reader of the YAML
  subset SKILL.md uses: flat mapping, one nested level, plain, quoted and block scalars.
  It rejects `: ` and a trailing `:`, ` #`, leading indicator characters, duplicate keys,
  unclosed quotes, undeclared multi-line values and null values, and names the line and
  column of each. Its self-test plants a `: ` value. The new `--frontmatter <SKILL.md ...>`
  mode checks copies installed anywhere.
- `test/test_validate.py` (new, 25 tests): a planted case for each rejected shape, block
  and quoted scalar semantics, every shipped SKILL.md, the CLI mode, and the whole-repo
  validation.
- `building-fabric-services/SKILL.md`: the description is now `>-` with the same text
  (927 characters; the parsed value equals the old line byte for byte, under both this
  parser and PyYAML 6.0.3). The other two skills already passed the strict read (422 and
  815 characters).
- `.github/workflows/release.yml`: the packed-tarball smoke now checks
  `~/.agents/skills` for all three skills, checks that `~/.claude/skills` is not created,
  and parses the installed front matter strictly. Before this it asserted
  `~/.claude/skills/...`, which the 0.4.0 installer never writes, so the release job
  would have failed on its first real run.
- The validator now also syncs `SKILL-CARD.md` versions and the release smoke paths.
- Version 0.4.1 is set in `package.json`, both manifests, the three SKILL.md files,
  `SKILL-CARD.md`, `validate.py` and the CHANGELOG.
