## Where the run diverged

1. **The scope came from a peer's summary, not from the obligation's source.** The contract session's message listed
   the DEC-0060/0066 work; the brief's decision 2 then ruled that the kits have no Windows token reader. Both were
   wrong: the contract's CT-18 row named `token_acl_problem` and `windows-token.json`, and the kits do read their token
   file. Surfaced at stage 5 (build, while reading `fabric_service.py`); owned by stage 0 (the harvest read the
   message, not the row). Fixed: REQ-13, both kits ported, Windows CI green. **Next time:** when another session hands
   over obligations, read the owning row in its repository (here the contract's `docs/backlog.md` CT-18) in full
   before the REQ table closes; a summary is a pointer, never the scope.
2. **One planted defect survived** (the JS kit comparing revocation refs after `String()`): the vectors held no case
   where the types differ. Surfaced at stage 6 (the mutation pass); owned by stage 5 (tests followed the vectors only).
   Fixed with an exact-type test in both kits. **Next time:** for every rule a decision states as "exactly", add a
   case where only the type differs.
3. **Disk pressure from a dereferenced `node_modules` copy** (376 MB) while the machine was at 0 bytes free. **Next
   time:** stage a dependency tree by symlink, never `cp -r`.
