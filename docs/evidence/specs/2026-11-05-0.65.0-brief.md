# 0.65.0 brief: no URL with credentials in a shipped file (FAA-211)

project-observatory's finding (board thread `44cd5502`, OBS-326, 2026-11-05): it wanted to vendor the kit modules
`fabric_connections`, `fabric_base` and `fabric_secrets` from 0.63.0 and rolled back, because its public release check
(`credential-url`, a pattern of the shape `https?://user:password@`) refused the examples in `fabric_secrets.py`'s
docstrings, and a product that vendors kit modules by their byte digests cannot edit them.

## Decisions

- D1. The examples stay (they document the readings the code guards against) and name their scheme in angle brackets,
  `<https>://u:pw@h`, which no credential-URL detector reads as a URL. No code changes; `kit.json` carries the new
  digests.
- D2. The check covers what a product can vendor or ship: `bin`, the whole plugin (modules, references, skills),
  README.md and SECURITY.md. The CHANGELOG is a record of released notes and keeps its examples as written; tests are
  not shipped and build such URLs from parts.
- D3. The check's pattern is wider than the products' own: any scheme, no slashes, backslashes and `///`, so every
  reading the kit documents is caught, not only `https://user:password@`.
