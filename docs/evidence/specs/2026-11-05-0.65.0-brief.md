# 0.65.0 brief: no URL with credentials in a shipped file (FAA-211)

project-observatory's finding (board thread `44cd5502`, OBS-326, 2026-11-05): it wanted to vendor the kit modules
`fabric_connections`, `fabric_base` and `fabric_secrets` from 0.63.0 and rolled back, because its public release check
(`credential-url`, a pattern of the shape `https?://user:password@`) refused the examples in `fabric_secrets.py`'s
docstrings, and a product that vendors kit modules by their byte digests cannot edit them.

## Decisions

- D1. The examples stay (they document the readings the code guards against) and name their scheme in angle brackets,
  `<https>://u:pw@h`, which project-observatory's `credential-url` pattern and this repository's check do not read
  as a URL. No code changes; `kit.json` carries the new
  digests.
- D2. The check covers what the npm package ships, read from package.json `files` (and package.json itself). The
  CHANGELOG ships too but is a record of released notes and no kit module, and keeps its examples as written. Tests
  are not shipped: the new one builds its URLs from parts, the others keep theirs.
- D3. The check searches two patterns: the products' own (project-observatory's `credential-url`) and one wider in
  scheme and slashes (any scheme, no slashes, backslashes, `///`, a tab among the slashes), so a line either refuses
  fails here first.
