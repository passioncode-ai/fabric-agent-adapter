# 0.75.0 brief: the Fabric communication agent template (FAA-262)

The operator decided on 2026-11-07 that every agent handling what people send works as one pipeline, and asked for a
template prompt in Fabric's agent templates that the agents are then told to adopt. The pipeline was measured that day
by an answering agent's session and this repository's session together (three runs on 56 real questions and 19
written batches, two judges of different vendors; the evaluation lives in that agent's private repository). That
session audited the estate's answering agents and wrote the template; this repository releases it.

## Decisions

- D1. The template is a reference page of creating-fabric-agents, `references/communication-agent-template.md`, beside
  `agents-that-answer-people.md`, because fabric-workspace's S2 (`knowledge/system/templates.md`) leaves the template
  format open until W1. When a `templates/` folder with a schema exists, it moves to `templates/communication-agent/`.
- D2. The text stays neutral, as the repository is public: no agent, product or person of the estate is named; numbers
  are one estate's field evidence, never a forecast. Rules 8 and 9 of the prompt name the vault and the channel's
  transport generically (for example Project Observatory; the estate's own Telegram sending service where it has one).
- D3. The steps are the rule; each step's model follows the project's own replay set (section 7), as the estate's model
  guide says («A switch must win on the project's own set»).
- D4. `models-and-providers.md` names the default model key limit (USD 100 a month unless the operator names more) and
  the agent's own stop under it.
- D5. Guidance only: no kit module, probe rule, hook or contract pin changes; `kit.json` moves its version with the
  release.

## Acceptance

- `python3 test/validate.py`, `python3 -m unittest discover -s test`, `npm test` and both `claude plugin validate
  --strict` pass.
- The scenario eval `a-channel-agent-starts-from-the-communication-template` and the new trigger query are in
  `test/evals/creating-fabric-agents/`.
- Three blind readings (unit, seam, product), two clean rounds in a row on the release commit.
