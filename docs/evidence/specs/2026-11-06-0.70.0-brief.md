# 0.70.0 brief: the launcher's one folder and the administrator's copy (FAA-237), Fabric's rule for the gate (FAA-231)

Status: implemented on branch `agent/faa-0.70.0`, 2026-11-06.

## Decisions

- D1 (FAA-237, 1). On macOS, `PASSIONCODE_APPLICATIONS` set to an absolute folder is the only candidate place, as
  the launcher's `appsDir` installs every app there (board thread `cb1df3d5`, `b54967ee`). An empty or relative
  value is not a place the launcher would use from another folder, so the default order holds. Other platforms
  ignore it (the launcher's rule is macOS').
- D2 (FAA-237, 2). Root's copy outside the home still runs (0.69.0 D7); `status` names it the administrator's copy,
  which the launcher does not update (its doctor's word for `/Applications`), in the `fabric-mcp:` line and as `administratorsCopy`.
- D3 (FAA-231). Fabric's `board.read-at-start` took the adapter's slot condition (main `dbfbfce4`, agreed in thread
  `1add3c03`, `57a8f25c`), so the references cite it instead of calling the condition the adapter's own.
- D4 (words). SKILL.md stays under 4750 words: "at all", "also" in the Hermes line and "neither ... nor" became
  shorter; "your calls also renew the claim" stays (any call renews, not only the heartbeat).
- D5 (readings rounds 1 to 3). `launcher_folder(env)` takes only a value starting with `/` (the launcher's `appsDir`
  takes any non-empty value as it is, `~/DATA/passioncode` `feat/pc-145-apps-per-user` `bd22566` `lib/catalog.js:83`,
  so a relative value or a literal `~` would be a folder under the launcher's working folder: no place another
  process can find), never a traceback; POSIX on whatever host reads it (on Windows `/Volumes/Apps` has no drive).
  `status` names that folder in its install advice, its other-user branch and its `fabric-mcp:` line (`launcherFolder`
  in `--json`). Tests drop the variable from the host's environment; the owner tests skip where `os.getuid` is
  missing (the Windows CI job), and the administrator's assertion skips under root (the containers).
- D6 (readings round 2). Only Fabric's board rule took the slot condition; `com.enroll`'s description (`b8c0a38c`)
  did not, so FAA-231 stays open and the references say so. The administrator's label is about the copy `status`
  found (the adapter's inference; with the launcher's folder set its doctor names no shared copy).

- D7 (readings round 3). A launcher's folder that already holds another user's `Fabric.app` is not proposed again:
  `status` says to unset `PASSIONCODE_APPLICATIONS` and use `~/Applications`, the launcher's own advice for a bundle
  the user cannot write (`bd22566` `lib/catalog.js:159`).
