# 0.64.0 brief: the retro after work (FAA-206 part 1)

Owner's words (2026-11-04, relayed on the board by Fabric, thread `f7758225`): every agent's work is logged and
analysed, with a feedback and improvement loop after each agent's work. Fabric's `fabric_whoami` carries the
obligation `retro-after-work` since `e1eecec0` (ADR-0188 §5, ADVICE): when a piece of work ends (a claim released as
done, or the session about to end), write a retro in the same turn: `observatory_lesson` (one class key per lesson)
for what went wrong and what would have prevented it, insight/1 lines for what was learned about the product, or one
line that there is nothing.

## Decisions (made from the sources; no material unknown left)

- D1. The moment a claim is released as done is seen by a Claude Code `PostToolUse` hook on Fabric's release tools
  only (`fabric_work_release` with `how` or `outcome` done; the older `fabric_task_release` with `outcome`
  succeeded), the ending read as Fabric reads it (`how ?? outcome`). It adds one line of context naming the retro.
  Any other release (let-go, handed-over, failed), any other tool and a release Fabric refused print nothing: Fabric
  refuses a release with an ordinary answer `{released: false, code, reason}`, never with `isError` (readings 1), so
  the answer's text decides; an answer the hook cannot read keeps the line.
- D2. No hook can speak to the model when a session ends (`SessionEnd` output is not shown to it), so the session
  start preamble names the retro at the end of the work in one clause; the dispatched run's exit contract already
  has it (step 7, 0.63.0).
- D3. The reminder fires in every session that calls the tool, a session Fabric launched included: Fabric injects no
  per-release line, and the obligation is the same.
- D4. Codex and Kimi get no post-tool hook from `install-host-hooks` in this release (recorded, not measured).
- D5. "The service kit gives an adapted agent the same obligation": creating-fabric-agents' practices and its
  SKILL.md checklist say an agent built with the kit closes each piece of work with the retro, and the
  adapting-projects checklist says so for an adapted project. No kit module changes; `kit.json` moves with the
  release version only.
