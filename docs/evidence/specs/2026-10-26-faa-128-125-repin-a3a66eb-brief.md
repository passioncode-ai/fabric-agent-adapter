## N-11 design: one instance per context

**What it guarantees.** A service started for a context runs as that context's one instance on this machine: its own
instance name, descriptor, data, log and cache folders and instance lock; a second copy for the same context exits 75
as today; an organization's instance runs only under a placement of this machine's estate record that names an
unrevoked share grant for that context, inside the grant's window; a data folder never changes context.

**Python (`kit/fabric_context.py`, L3 after `fabric_descriptor`).**

```python
EXIT_CONTEXT_REFUSED = 78                       # EX_CONFIG; 75 stays "already running"
CONTEXT_MARKER = "fabric-context.json"

class ContextRefused(ServiceError):             # .code: context-invalid | record-required | placement-missing
    code: str                                   #        | grant-refused | grant-window | context-mismatch

def context_instance_name(context: str, *, personal_instance: str = "default") -> str: ...   # D15; raises ContextRefused
def context_instance(service_id: str, context: str, *, record: Optional[dict] = None,
                     machine_id: Optional[str] = None, agent_ref: Optional[str] = None, at: Any = None,
                     personal_instance: str = "default", services_directory: Optional[Path] = None) -> Dict[str, Any]:
    """Pure: no folder, file or lock. {"context", "kind": "personal"|"org", "org"?, "instance", "key": "<id>.<instance>",
    "dirs": {"data", "logs", "cache"}, "descriptorPath", "grant"?: {"id", "startsAt"?, "expiresAt"?}}."""
def hold_context_instance(service_id: str, context: str, *, record=None, machine_id=None, agent_ref=None, at=None,
                          personal_instance="default", wait_seconds=None, env=None, argv=None
                          ) -> Tuple[Dict[str, Any], InstanceLock]:
    """context_instance, then hold_single_instance(dirs["data"]), then the marker (D17). A refusal prints one
    sentence and exits 78; the lock's own refusals exit 75 as hold_single_instance does."""
```

**Node (`kit/fabric-context.mjs`).** `EXIT_CONTEXT_REFUSED`, `CONTEXT_MARKER`, `ContextRefused`,
`contextInstanceName(context, {personalInstance})`, `contextInstance(id, context, {record, machineId, agentRef, at,
personalInstance, servicesDirectory, platform})`, and `async holdContextInstance(id, context, {..., waitSeconds, sleep,
clock, exit, env, argv})` with `exit` injectable as `holdSingleInstance` has it (`fabric-lock.mjs:204-206`).

**The steps of `context_instance`.**

1. `fabric_estate.parse_context(context)` (`fabric_estate.py:90`): `None` refuses `context-invalid` (D20).
2. The instance name (D15) and `fabric_paths.instance_dirs(service_id, instance)` (D16); `descriptor_path(service_id,
   instance, services_directory)` (`fabric_descriptor.py:99`).
3. Personal: no record needed. A given record is read only for this machine's personal placement of `agent_ref`; one
   that names a grant refuses `grant-refused` (D20).
4. Organization: no record refuses `record-required`; no `machine_id` or `agent_ref` refuses `record-required` too
   (D18). `fabric_share.instance_share_grant(record, machine_id, agent_ref, context, at_ms)` answers:
   - the placement among `machines[id == machine_id].packages[]` with `agentRef` equal and `context` equal as written
     (absent `context` is `personal`, `fabric_estate._context_of`); none refuses `placement-missing` (`FAC-SEM-074`'s
     reading);
   - `fabric_estate.placement_grant_findings(record, placement)` (the public export of `_placement_grant_problems`,
     `fabric_estate.py:751-776`: the grant exists by normal form, its context is the placement's as written, it is
     not revoked); any finding refuses `grant-refused` with the findings' messages;
   - the grant's `startsAt` and `expiresAt` read by `fabric_time.parse_rfc3339_ms`, `at` from `fabric_time.clock_ms`;
     outside the window refuses `grant-window` (D19); an unreadable instant refuses too.
5. The answer carries the grant's id and window, never the record.

**The steps of `hold_context_instance`.** `context_instance` (any refusal: one sentence on stderr naming the code and
the context, exit 78, nothing created); `fabric_lock.hold_single_instance(dirs["data"], wait_seconds, env=env,
argv=argv)` (its markers, its 300 s supervised wait, its exit 75); the marker `<data>/fabric-context.json` read, then
written with `fabric_paths.atomic_write(..., mode=0o600)` when absent; a marker naming another context or instance
releases the lock and exits 78 (`context-mismatch`). The lock comes before the marker is written, so two copies never
race on it.

**Kit order (`kit.json`).** Python: `fabric_page_links` after `fabric_protocols`; `fabric_a2a` after
`fabric_connections`; `fabric_context` after `fabric_descriptor`. Node: the same three in the same places. `fabric_share`
(L2) needs no new import (Python already imports `fabric_estate` and `fabric_time`; Node reads instants with
`estateTime` from `fabric-estate.mjs:9`); `fabric_paths` (L1) imports
only `fabric_base` for `_INSTANCE`. `fabric_descriptor` imports `fabric_a2a`; `fabric_interop` imports
`fabric_page_links`. `test_the_order_is_a_layering` holds it.

**Tests seen red first.** `test/fixtures/kit-context-cases.json` (shared by both twins): names (`personal` to
`default`, `org:acme-rehearsal` to `org-acme-rehearsal`, `org:Acme`, `org:acme_x`, a 128-character id, an id ending in
`-` and 10 hex digits, each against `_INSTANCE`); refusals (no record, no placement, a placement in another context, a
grant of another context, a revoked grant, a grant by its non-normal id spelling accepted, a window not started, a window
ended, `Personal`, a personal placement naming a grant). Python and Node: a second `hold_context_instance` on the same
context exits 75; a refusal creates no folder (the data folder does not exist after it); a marker of another context
exits 78 and leaves the lock free; the personal instance's folders equal `service_dirs`.
