# 0.67.0 brief: FAA-210's items that need code

FAA-210 collects follow-ups from the 0.64.0 to 0.66.0 readings. This release takes the ones that need code and that
no other task owns.

## Decisions

- D1. After `com.effect_begin` a run whose work outlasts it completes the request `failed_known` with the state it
  observed, as Vesta's run does (board thread `1add3c03`): the request is `in_progress`, and a next run could only
  settle it as `outcome_unknown` with `com.reconcile`. A request still accepted, with no effect begun, is left for the
  next run as before. The exit contract says it in its step 4 and stays under Hermes' 4000 characters by leaving
  "(no run starts that close to it)" to the reference.
- D2. A hook reads at most 4 MiB of bytes (`HOOK_INPUT_CAP`), decoded as UTF-8 with a byte order mark dropped and a
  byte that is no UTF-8 read as U+FFFD; more is read as nothing. 4 MiB holds a million characters in any script,
  what 0.63.0 read as text.
- D3. The dashboard-kit notice reads its stdin the same way (`read_stdin_text`), 64 KiB as before.
- D4. Where insight/1 lines go is the project's `insights/` folder, the place Observatory named for its reader
  (OBS-331, board thread `f7758225`); the retro line and the preamble say it.
- D5. `hooks.json`'s description and AGENTS.md's hook list name every exception to "silent in a session Fabric
  launched". The 0.64.0 CHANGELOG entry is a record and is not reworded.
