# Brief: 0.52.0, the repin to `v0.1.0+2026-10-26.12` (DEC-0126 to DEC-0137)

Date: 2026-10-26. Rows: FAA-138 (the repin), FAA-134 (DEC-0126, the operator's `source`), FAA-141 (Fabric TO-2,
already on this branch), FAA-135's job step (decision D2). Impact map:
[2026-10-26-faa-138-134-repin-1197a90d-impact-map.md](2026-10-26-faa-138-134-repin-1197a90d-impact-map.md), every
file and line cited there at the contract tag `v0.1.0+2026-10-26.12` (`1197a90d`).

## Objective

Pin the kits to the contract release `v0.1.0+2026-10-26.12`, port what it makes normative for a surface the kits
already implement, and record as backlog rows what it adds that the kits do not implement. Due 2026-11-02.

## Requirements

- REQ-1: `fabric-contract.lock.json` names `1197a90d`; every lockstep constant and live mention moves with it
  (impact map section 8); `a3a66eb0`, `52c7d798` and `e6c4fc16` stay supported where the last repin kept them.
- REQ-2: the protocol register in both twins equals the contract's at `.12` (nine new entries).
- REQ-3: DEC-0126. A mandate and a decision may carry `source`; the kits read it, keep it in the record they hand
  back and on a hand-over, build it with a `source=` option, and send it only to a callee that lists
  `operator-source/1` (decision D3); never through Fabric's hub (OA-7). Nothing logs, reports or renders `source`.
- REQ-4: DEC-0136 closes: the by-name override of "a capability list under no list" goes, the vendored vector says
  `false` itself, and both twins run the `handOn` group (30 cases).
- REQ-5: DEC-0128. `hub_key_certified` takes the instance's context; `verify_delegation` and `delegation_gate` take
  `estate_context`; the estate rules check context hub keys (FAC-SEM-147 and the changed 073, 076, 114, 134).
  `fabric_estate` splits so every module stays under 1000 lines.
- REQ-6: DEC-0135. The board docs say who an answer reaches and when to send `deliverTo: "thread"`; the kit's
  fenced replies carry none.
- REQ-7: DEC-0130 and DEC-0137 wording in the delegation and estate references.
- REQ-8: FAA-135's job step: a job's input request reads `_meta.mandate` (contract `conformance.md:219`).

## Decisions

- D1. Pin `1197a90d` (`v0.1.0+2026-10-26.12`), the contract's latest release on 2026-10-26.
- D2. FAA-135's job step is ported now (REQ-8), not carried as an exception: the pin rule says a normative duty on a
  surface the kit implements is ported at the pin, and `conformance.md:219` already required it at `.2` (0.51.0's
  brief D26 left it out). The rest of FAA-135 (the board responder) stays a row.
- D3. `request_meta` takes an explicit `target_protocols` (the callee's well-known `protocols`). Without it, or when it
  lacks `operator-source/1`, `source` is stripped before sending and kept only in the caller's own record. Through
  Fabric's `agent.call` it is never sent (the directory lists no `protocols`; OA-7).
- D4. A kit service that reads `source` (an `McpToolServer` with `agent_id`) lists `operator-source/1` in its
  well-known `protocols` by default; a service that builds its own list is told so in `references/interop.md`.
- D5. An organization instance whose context the record does not pin: documented, not refused at start.
  `hub_key_certified` already refuses its tokens (`kid-not-certified`). DEC-0127 says Fabric writes `organizations`
  only once every reader is pinned at or after it, so a refusal now would stop every organization instance on today's
  records. Revisit at the next pin.
- D6. Not kit surfaces at this pin, each a backlog row: the membership reader (DEC-0127's verifiers, FAC-SEM-145,
  146), the member list, draft exchange and relay (DEC-0129, 0131, 0133, 0134), the machine report (DEC-0132),
  `source` through the hub, the DL-29 helper, board delivery vectors (CT-166), a protective `approval/1` (CT-168).
- D7. FAA-138's module list is corrected: hub move, revocation delta and window lease have no kit port and changed
  only in comments or code the kit does not implement; `fabric_hub` needs nothing.
- D8. `fabric_estate` (941 lines) splits its record rules into a new module, `fabric_estate_rules`, which `fabric_estate`
  re-exports so callers keep their import. Amended at N4: it is listed just BEFORE `fabric_estate` in `kit.json`,
  since a module imports only modules listed before it (`test_the_order_is_a_layering`).
- D9. Nodes: N1 repin and N2 register first (mechanical, one worktree); N3 (source and the mandate close-out, with
  REQ-8) and N4 (context hub keys) in their own worktrees on top; N5 and N6 (docs) on the integration branch; N7 the
  release record. Each node's checks are in the impact map, section 9. Verification: blind seam and product readings
  until two consecutive clean rounds; `npm test` once at the end, disk permitting (3 GB free at this writing).
