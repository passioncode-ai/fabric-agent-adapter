# Fabric Agent Adapter — delivery brief

Date: 2026-08-27
Status: accepted by the implementation run

## Outcome

Ship a private, portable Agent Skill that helps an author adapt an existing agent,
API, MCP server, A2A peer, or terminal tool to the Fabric Agent Contract. The skill
must inspect before changing, select one profile per capability, scaffold a provider
bundle without overwriting existing work, and report exactly what has and has not
been verified.

## Distribution

- GitHub organisation: `passioncode-ai`

- Skill: `adapting-projects-to-fabric`
- Visibility: private
- Initial version: `0.1.0`

The contract repository remains normative. This repository contains workflow,
templates, and deterministic checks tied to the explicit pin; it must never present
its templates as a newer standard.

## Target-project file contract

The adapter may seed only these paths unless an author explicitly implements the
runtime-specific adapter elsewhere:

```text
fabric-agent.json
fabric-contract.lock.json
fabric/
  schemas/
    capability-input.schema.json
    capability-output.schema.json
  fixtures/
    admission-input.json
  probes/
    assertions.md
  FABRIC-CONFORMANCE.md
```

`fabric-agent.json` is the discovery declaration. `fabric-contract.lock.json`
records the normative repository, version, and immutable commit. Everything under
`fabric/` is provider-owned supporting material. No secret values, account tokens,
or project credentials may be written to these files.

## Profile rule

- Use A2A `1.0` when the remote peer owns an autonomous task lifecycle.
- Use MCP `2026-07-28` when Fabric owns the loop and invokes bounded capabilities.
- Use `fabric-local-runner/0.1` for an installed terminal process.
- Do not claim compatibility for a web UI with no stable API, protocol, or CLI.

The decision is per capability, not per vendor or repository. Ambiguous evidence
produces an `undetermined` recommendation and a named question; it does not guess.

## Verification model

The generated conformance report has four independent gates:

1. declaration shape;
2. exact protocol revision and connection surface;
3. bounded semantic probes;
4. readiness for a project binding.

The local helper may prove structural readiness. Full schema validation requires the
pinned contract checkout. Live negotiation, semantic admission, and binding require
a Fabric host and therefore remain `NOT VERIFIED` until their actual receipts exist.

## Safety and degradation

- Inspection is read-only.
- Scaffolding creates missing files only; replacement requires `--force`.
- Probe templates use a `none` side-effect ceiling by default.
- Outputs from external projects and protocols are untrusted data.
- If the contract checkout, runtime, or credentials are absent, the skill names the
  skipped gate and exact next action instead of weakening the result.

## Acceptance

- The skill triggers for explicit Fabric compatibility/adaptation requests and avoids
  general agent construction, project audits, or MCP client configuration.
- At least three protocol scenarios and about twenty trigger/non-trigger queries exist.
- The scaffolder and checker are Python standard-library only and tested.
- Repository, plugin, skill, and changelog versions agree.
- The house validator and strict Claude plugin validators pass.
- A private GitHub release can be installed or discovered from the repository.
