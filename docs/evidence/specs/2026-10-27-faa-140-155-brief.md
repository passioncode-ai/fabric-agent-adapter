# Brief: 0.53.0, the repositories a turn changed (FAA-140) and a moved responder slot stays moved (FAA-155)

Date: 2026-10-27. Due 2026-11-12. Rows: FAA-140 (Fabric CO-367, ask `ac92166e`, thread `c69ec4d3`), FAA-155
(contract CT-174 and CT-175, board `9ae0a498`).

## Requirements

- REQ-1 (FAA-140). The Stop hook finds the other Git repositories the turn changed: the turn's tool calls in the
  transcript (`file_path` of Edit, Write and NotebookEdit; `cd <absolute path>` and `git -C <path>` in Bash), each
  resolved with one `git rev-parse --show-toplevel` and one `git config remote.origin.url`, inside the hook's 1.5 s
  facts budget. Each is named `{host, owner, name}` from its `origin` (credentials and `.git` stripped). The start
  folder's repository and a repository with no `origin` are not named; at most 10; no local path leaves the hook.
- REQ-2 (FAA-140). They are spooled with the turn and sent as `repositories` on `fabric_session_observe` only when
  that tool's input schema lists `repositories` (as `observedAt` is detected today); otherwise nothing is sent and
  nothing changes for today's Fabric.
- REQ-3 (FAA-155). The kit's board responder remembers the generation it held per capability. When `com.status`
  shows that generation moved past it (the operator moved the slot), the responder ends its claims, leaves its
  accepted work held, and neither replaces nor re-enrolls on its own: not at recovery after a restart, and not when
  the new holder's lease lapses. Both twins.

## Decisions

- D1. The repository identity is `{host, owner, name}` (proposed to Fabric on `a8bdda7a`): `host` because both GitHub
  and Bitbucket are in use. Until Fabric's schema lists the field nothing is sent, so the shape can change before
  anything reaches Fabric.
- D2. The hook reads only the tail of the transcript (the current turn's entries, at most 512 KB from the end) and
  never reads message text, only tool names and the path arguments above.
- D3. FAA-155's moved-off rule is the contract's suggested option (board `9ae0a498`). The receiving side (CT-175, the
  host hands over the accepted requests) and `project.work` (CT-174) wait for Fabric's session surface: rows.

- D4. Amended at build: a second checkout of the start repository (a worktree or another clone, same `origin`) is not
  named either (N1), and the responder gains `take_back(capability)` / `takeBack(capability)`, the operator's act that
  brings a moved slot back (N2); a move back to this service's own session is detected once Fabric's session surface
  exists (CT-175).
