# 0.72.0 brief: ask the operator at every gate decline (FAA-241)

Fabric main `4f3c742a` (thread `1add3c03`, `40caf807`) changed `board.read-at-start` and `com.enroll`'s description: a
session whose `com.enroll` is refused `not_authorized` asks the operator with `fabric_question_ask` (the same `about`
and `commandId`) at every slot state, and sends `com.reply` only when the slot reads `absent` at generation 0.

## Decisions

- D1. The adapter takes the same rule for a run Fabric started on a board request (the exit contract's step 3,
  `references/on-demand-session.md`) and for a live session (`references/project-board.md`): at a slot that is
  `stale`, `active` or `absent` at a later generation, no `com.reply` (it would take the request from the service) and
  still the question, which answers no request; then the error rule holds and the request stays queued.
- D2. The exit contract stays under Hermes' 4000 characters: "until Fabric's CO-506" became "until CO-506" (3996 at its
  longest, from 3999).
- D3. Step 6 still closes the workflow only once `com.get` reads the request answered; at another slot state the
  request is not answered, so the workflow stays open (the error rule) and the run writes the retro (step 7).

- D4 (readings round 1). Both scenario evals carry the rule (the live session's `answer-as-responder-or-reply` too);
  `on-demand-session.md` separates the no-reply branch, names a failed question in the in_progress checkpoint's
  `notes`, and names what opens the gate (before CO-506: a release with it, and at a held slot the service enrolling
  again; after it: the reason `board.own-respond` names and what lifts it, at every slot state). The exit contract's branch
  joins the question with a comma, not a semicolon (a semicolon separates step 3's cases).

- D5 (readings round 2). The gate question's text depends on Fabric's release, not on the slot alone (after CO-506 a
  held slot may have been a session's). A question asked when nothing was declined is still keyed by `gate-id`; its
  docstring, comment and SKILL-CARD say "refused", not "declined". A failed question at a held slot goes into one more
  in_progress checkpoint's `notes`. The paragraph about the requester reading the decline opens with "After the
  decline".
